# 同目录多任务与文件筛选

同一个源目录可以配置多个硬链任务。例如任务 A 将纪录片硬链到 `/media/A`，任务 B 将带季集编号的文件硬链到 `/media/B`。源文件保留，文件同时命中两个任务时，会在两个目标目录分别创建硬链。

## WebUI 设置

1. 创建两份配置，源目录都填 `/downloads`，目标目录分别填 `/media/A` 和 `/media/B`。原有后缀筛选和目录结构选项继续生效。
2. 创建两个「硬链」任务，分别选择对应配置。
3. 在任务编辑的「文件筛选」中打开「为此任务单独配置筛选规则」。任务 A 添加关键词列表；任务 B 添加命名规则，选择「季集编号」。
4. 点击「预览匹配结果」检查待硬链、已存在、缓存跳过和未匹配的文件。预览只扫描，不创建硬链或修改缓存；最多展示 100 条明细，统计覆盖全部扫描结果。
5. 保存任务，手动运行或分别设置定时执行。这里沿用现有定时扫描，也可以由下载完成脚本触发。

关闭任务独立规则时，使用配置文件中的 `fileFilter`。开启时，任务规则替代配置文件中的 `fileFilter`；原来的 `include` / `exclude` 仍会同时生效。未添加包含规则表示不增加包含限制，排除规则仍然有效。

修改任务规则或配置文件后，后续定时执行会读取最新配置。规则只决定之后创建哪些硬链，已经存在的硬链不会因为修改规则而自动删除。

## 配置文件示例

任务 A 的配置：

```javascript
export default {
  pathsMapping: { '/downloads': '/media/A' },
  include: ['mkv', 'mp4'],
  exclude: [],
  fileFilter: {
    mode: 'any',
    rules: [
      {
        type: 'keyword',
        values: ['纪录片', 'Documentary'],
        target: 'relativePath',
      },
    ],
    exclude: [{ type: 'keyword', values: ['预告', 'trailer', 'sample'] }],
  },
  keepDirStruct: true,
  mkdirIfSingle: false,
  openCache: true,
}
```

任务 B 使用相同源目录，将目标改为 `/media/B`，筛选改为：

```javascript
fileFilter: {
  rules: [{ type: 'preset', values: ['episode'] }],
},
```

两个任务均可开启缓存，相互之间不会因为源文件相同而跳过。

## 规则语义

每条规则的 `values` 是字符串列表，命中任意一个值即满足该条规则。WebUI 中可按行批量粘贴关键词、正则和 Glob。

| 字段            | 取值             | 说明                                                         |
| --------------- | ---------------- | ------------------------------------------------------------ |
| `type`          | `keyword`        | 字面包含匹配；`[组名]` 等字符不会当成正则                    |
| `type`          | `regex`          | 正则表达式，例如字符串 `'S\\d{2}E\\d{2}'`；不要加 `/ /` 包裹 |
| `type`          | `glob`           | 通配符，例如 `**/*.mkv`；涉及目录时选择 `relativePath`       |
| `type`          | `preset`         | 命名预设，见下表                                             |
| `target`        | `filename`       | 默认，仅文件名，包含后缀                                     |
| `target`        | `parent`         | 源目录内的直接父目录名；源目录下的散装文件使用空字符串       |
| `target`        | `relativePath`   | 相对于源目录的路径，分隔符为 `/`，不包含源目录名称           |
| `caseSensitive` | `false` / `true` | 默认忽略大小写                                               |

包含规则 `rules` 之间由 `mode` 控制：默认 `any` 表示任意一条，`all` 表示全部满足。排除规则 `exclude` 命中任意一条即排除，优先于包含规则。想表达「包含关键词且满足某个正则」，添加两条规则并选择 `all`。

| 命名预设     | 识别示例                                                                             |
| ------------ | ------------------------------------------------------------------------------------ |
| `jav`        | `IPZZ-037`、`MKMP-755`、`FC2-PPV-3152570`，排除 IMG / PHOTO / iShot 等常见图片命名   |
| `episode`    | `Show.S01E02.mkv`、`Show_1x02.mkv`                                                   |
| `date`       | `2026-10-23`、`2026.10.23`、`2026_10_23`；检查格式及月份、日号范围，不判断日历有效性 |
| `resolution` | `720p`、`1080p`、`1080i`、`2160p`、`4K`、`8K`                                        |

配置中的正则需要遵循 JavaScript 字符串转义，例如 `'S\\d{2}E\\d{2}'`。WebUI 规则输入框直接填写 `S\d{2}E\d{2}`。正则、命名预设或匹配值无效时会报错，不会自动退回匹配全部文件。

## 缓存兼容

新缓存以 `{ source, target }` 记录成功创建的硬链，目标是最终文件路径，因此 A 的缓存不会影响 B，调整目标或目录结构后也可以重新创建。重名失败的文件不进入缓存，且不会覆盖原有目标文件。开启缓存时，手动删除某个目标硬链后仍会跳过该目标，这是原有缓存行为。

旧版本缓存中的字符串路径仍保留，用于反向修剪时保护源文件；由于旧记录没有目标信息，不能用它跳过新硬链任务。升级后首次运行可能重新创建以前手动删除的硬链，实际已经存在的硬链仍按原有 inode 检测跳过。缓存文件仍为原来的 `cache-array.json`，可以在原有缓存编辑器中查看或清理。

筛选也应用于 prune 的候选文件；`relativePath` 以当次扫描目录为根。若硬链时压平了目录结构，源目录和目标目录的相对路径可能不同，此时建议 prune 使用文件名规则。`deleteDir: true` 仍遵循原有整目录删除语义。
